# 打包范围与便携化改动

## 来源

2026-10-14 从项目负责人提供的 UltraGo 源目录复制 MAGMa v8 的生成入口及导入链。
原文件校验值和实际依赖版本记录在 `source_manifest.json`。原始远端文件保持原样。

## 所含文件

- `fragments/magma/op/Magma4MassSpecGYm.py`：用户指定的生成脚本。
- `fragments/magma/op/fragmentation_op_v8.py`：实际使用的碎裂引擎。
- `common.py`、`chem_utils.py`、`misc_utils.py`、`parallel_utils.py`：导入所需的本地模块。
- 各级 `__init__.py` 及 `fragmentation.py`：保留原包初始化所需依赖。
- 固定版本依赖、环境文件、两条合成示例和带日志的运行包装脚本。

没有附带训练模型、完整 CSV/JSON、历史 pickle 标签或服务器访问配置。
下游历史 `extract_fragments.py` 不在发布范围内，其问题只作为上下文记入说明。

## 对原有 Python 源码的唯一改动

将生成脚本内写死的机器专属 `sys.path` 改为从 `__file__` 定位仓库根目录。
因此既支持模块执行，也支持脚本直接执行；不要求原机器的目录结构。

没有修改碎裂枚举、候选质量、PPM 筛选、打分、原子编号、输出 schema、失败处理、
默认参数或规范化逻辑。新包装脚本只选择输出位置、保存配置日志，并拒绝覆盖已有
输出目录。`--no-canonicalize` 是原本已有选项，是否启用由调用者显式决定。

## 已有操作问题

- 原脚本依赖机器专属路径：本副本已改为相对仓库根定位。
- 原脚本会覆盖指定输出：包装脚本要求新输出目录；直接 CLI 仍保留原行为。
- 原脚本不保存完整运行配置：包装脚本记录参数、Python/包版本、日志和退出码。
- 原脚本没有断点续算：本次没有添加，不得把重新执行称为续算。

## 后续修改

修复已知算法/标签问题时，应保留本次来源记录，另建明确提交，并使用真实数据做
映射、覆盖、错误分类和前后结果审计。两条合成示例只能作为接口验证。
